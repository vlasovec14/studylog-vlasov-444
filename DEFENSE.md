## Что сказать о проекте

«StudyLog позволяет зарегистрироваться, сохранить курс и вести конспекты уроков. В проекте есть встроенный пользователь User, модель курса Course и модель конспекта LectureNote. Курс принадлежит пользователю, а конспект — курсу. На личной панели я показываю только данные вошедшего пользователя. Создание и изменение проходят через ModelForm. Для шаблонов использую наследование base.html, для защиты форм — CSRF».

## Что показать преподавателю

1. Запуск `start.cmd` или `manage.py runserver` и открытие главной страницы.
2. Регистрацию своего аккаунта и пустую личную панель.
3. Добавление курса: название, автор/платформа, часы.
4. Добавление конспекта с номером урока, темой, содержанием и датой.
5. Панель с числом конспектов и последней датой обучения.
6. Проверку ошибок: номер урока 0, повторный номер, отрицательная длительность, будущая дата. Браузер может остановить неверный ввод раньше сервера; серверные проверки покрыты тестами.
7. Редактирование и удаление. Открытие страницы подтверждения ничего не удаляет: действие выполняет POST.
8. Два аккаунта: скопировать адрес курса первого пользователя, выйти, войти вторым и открыть адрес. Должна появиться ошибка 404.
9. `manage.py test` и `git log --oneline`.

## Минимум Python

`name = 'Никита'` — присваивание строки переменной. `=` присваивает, `==` сравнивает. `def` объявляет функцию; `return` возвращает результат. Отступы определяют блок кода. `if` выбирает ветку. `from ... import ...` подключает готовый код. Список записывают в `[]`, словарь с парами ключ–значение — в `{}`.

```python
context = {'course': course, 'notes': notes}
return render(request, 'journal/course_detail.html', context)
```

Здесь context — словарь. Строки `'course'` и `'notes'` задают имена, которые будут доступны шаблону. Значения справа — объекты Python. `request` — объект HTTP-запроса браузера. `render` создаёт HTTP-ответ из шаблона и контекста.

`class Course(models.Model)` объявляет класс, наследующий Django Model. Экземпляр Course представляет конкретный курс. `self` — ссылка на текущий экземпляр. `__str__` задаёт его читаемое строковое представление.

Декоратор `@login_required` оборачивает представление проверкой авторизации. Пользователь без входа перенаправляется на страницу входа. Декоратор `@require_http_methods` ограничивает допустимые HTTP-методы.

## Как проходит запрос

При GET `/dashboard/` Django находит адрес в urls.py и вызывает dashboard. `login_required` проверяет вход. Представление выбирает Course с владельцем `request.user`, рассчитывает статистику и передаёт контекст в шаблон. Шаблон наследует base.html и формирует HTML. Браузер отображает готовую страницу и CSS.

При POST формы Django сначала проверяет CSRF. Представление создаёт форму с request.POST, вызывает `is_valid()`, затем сохраняет данные и перенаправляет на GET. Такое перенаправление уменьшает риск повторной отправки формы при обновлении страницы.

## Модели и связи

```python
user = models.ForeignKey(settings.AUTH_USER_MODEL,
                         on_delete=models.CASCADE)
course = models.ForeignKey(Course, on_delete=models.CASCADE)
```

ForeignKey — внешний ключ, связь «один ко многим»: у пользователя много курсов, у курса много конспектов. CASCADE означает, что удаление пользователя удалит его курсы, а удаление курса — его конспекты.

`CharField` — короткий текст, `TextField` — длинный, `DateField` — дата, `DecimalField` — десятичное число с фиксированной точностью. Для продолжительности выбрано DecimalField, чтобы хранить дробные часы без особенностей двоичных float.

В LectureNote положительный номер контролируется валидатором и ограничением БД. Уникальность номера внутри курса не мешает иметь урок №1 в двух разных курсах.

`makemigrations` создаёт Python-файл с изменениями структуры БД. `migrate` применяет миграции. Файлы миграций отправляются в Git, локальная база — нет.

## Почему чужие данные недоступны

```python
course = get_object_or_404(Course, pk=pk, user=request.user)
```

Поиск ограничен одновременно номером курса и текущим пользователем. Чужой курс выглядит как отсутствующий. Одного `login_required` недостаточно: он проверяет только факт входа, а не владельца конкретной записи.

Для конспектов фильтр проходит через связь: `course__user=request.user`. Двойное подчёркивание в Django ORM позволяет обратиться к полю связанной модели.

В формах нет полей user и course. Владелец нового курса берётся из request.user, курс конспекта — из уже проверенного сервером объекта. Подмена этих полей в POST не переносит запись другому пользователю.

## ModelForm и валидация

ModelForm строит форму по модели. В Meta явно указаны разрешённые поля. `is_valid()` проверяет данные, ошибки доступны в form.errors, нормализованные значения — в cleaned_data. Только после проверки вызывается save().

Проверки продолжительности и номера урока есть на сервере. `min` и `type` в HTML нужны для удобства, но пользователь может обойти браузер. `CheckConstraint` дополнительно запрещает нулевые значения на уровне базы. `UniqueConstraint` запрещает два одинаковых номера урока в одном курсе.

`clean_study_date()` отклоняет будущую дату. `clean_lesson_number()` даёт понятную ошибку при повторе номера. При редактировании текущий конспект исключается из поиска дубликатов.

## Шаблоны и защита

`{% extends 'base.html' %}` наследует общую страницу; block задаёт её заменяемую часть. `{{ course.title }}` выводит значение. `{% for note in notes %}` отображает уже подготовленный список. Агрегация и фильтрация находятся во views.py.

`{% url 'course_detail' course.pk %}` строит адрес по имени маршрута. При изменении адреса не нужно искать текст ссылки по всем шаблонам. `{% static %}` отдельно строит адрес CSS; ссылка `#main` — переход внутри текущей страницы.

`{% csrf_token %}` добавляет токен защиты POST-формы. Django сравнивает его с данными текущего сеанса. Это помогает не принимать поддельные изменяющие запросы от постороннего сайта. Выход и удаление выполняются POST-запросами.

Django экранирует пользовательский текст в HTML. Если записать `<script>...</script>` в конспект, он отображается как текст. В шаблонах не используется `safe` для содержимого заметок.

## Что означает прогресс

Count('notes') считает конспекты курса; Max('notes__study_date') находит последнюю дату изучения. Sum('duration_hours') суммирует длительности своих курсов. Эти вычисления делает ORM в views.py.

Процент завершения вычислять не из чего: в условии у курса нет общего числа уроков. Номер последнего урока не равен количеству изученных уроков. Поэтому прогресс — количество сохранённых конспектов, а часы — общий объём материалов.

## Частые вопросы

**Почему нет своей модели User?** Встроенной модели достаточно для регистрации, входа и связи с курсами.

**Где хранится пароль?** Django хранит его хеш с параметрами алгоритма, а не исходный текст. Сохранение пароля выполняет UserCreationForm.

**Что делает get_object_or_404?** Получает объект, соответствующий фильтру; если его нет — возвращает HTTP 404 вместо ошибки сервера.

**Чем GET отличается от POST?** GET получает страницу. В этом приложении POST создаёт, изменяет и удаляет данные или завершает сеанс.

**Почему для чужого курса 404?** Чтобы не раскрывать наличие записи и одновременно исключить доступ к ней.

**Зачем .gitignore?** Он исключает окружение, локальную базу, кэш и настройки IDE из следующих добавлений в Git. Уже отслеживаемые файлы сам по себе не удаляет из истории.

**Почему не копировать db.sqlite3 преподавателю?** Структура восстанавливается миграциями, личные данные в репозиторий не передаются.

**Почему интерфейс без JS?** Задание требует серверный рендеринг Django Templates и обычный CSS. Для этого функционала JavaScript не нужен.

**Что проверяют тесты?** Реальные запросы и ограничения: чужие записи, подмена владельца, ошибки форм, CSRF, удаление, вход и вывод HTML. Они выполняются на отдельной тестовой базе.
