# StudyLog — дневник достижений и вебинаров

Самостоятельная работа по Django. **Никита Власов, группа 444, вариант 4.**

Приложение хранит курсы, вебинары и учебные материалы, а также конспекты пройденных уроков. У каждого пользователя своя коллекция. Проект реализован на Python 3.14, Django 6.0 и SQLite, без сторонних JavaScript-библиотек.

## Быстрый запуск на этом компьютере

Открой папку проекта и дважды нажми **start.cmd**. В этой локальной папке уже подготовлено окружение `.venv` с Python 3.14. Сервер применит миграции и запустится по адресу <http://127.0.0.1:8000/>. Зарегистрируй собственный аккаунт, затем добавь курс и первый конспект. Пароль выбирай сам; пароль для аккаунта в дневнике не обязан совпадать с GitHub.

Окно сервера должно оставаться открытым. Для остановки нажми `Ctrl+C`. Если порт 8000 занят, запусти из терминала `.\.venv\Scripts\python.exe manage.py runserver 8001` и открой <http://127.0.0.1:8001/>.

## Установка из архива или GitHub

На новом компьютере сначала установи **Python 3.14** с [официального сайта Python](https://www.python.org/downloads/) вместе с Python Launcher. После этого можно воспользоваться `start.cmd` или выполнить команды в PowerShell из папки, содержащей `manage.py`:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py runserver
```

Архив и Git-репозиторий не включают виртуальное окружение, SQLite-базу, тестовые аккаунты или личные данные. Они создаются локально. В PyCharm выбери существующий интерпретатор `.venv\Scripts\python.exe` из этой папки. Python 3.13 из прежнего lab1 не соответствует требованиям нового задания.

## Возможности

- Регистрация со встроенными проверками пароля, вход и выход через POST.
- Главная страница и защищённая личная панель.
- Добавление, просмотр, изменение и удаление курсов.
- Добавление, изменение и удаление конспектов.
- Подсчёт курсов, конспектов, общего объёма материалов и последней даты занятия по каждому курсу.
- Личные записи недоступны другому пользователю даже по прямому адресу и при подмене данных POST-запроса.
- При удалении курса каскадно удаляются его конспекты.

Прогресс отражается количеством уроков с конспектом. Процент завершения не вычисляется: общее число уроков не задано в условии. Общие часы — продолжительность материалов, а не фактически затраченное время.

## Проверка требований варианта 4

| Требование | Реализация |
|---|---|
| User и две собственные модели | Встроенный User, Course, LectureNote |
| Название, платформа/автор, длительность курса | Поля Course.title, platform, duration_hours |
| Номер, тема, содержание и дата урока | Поля LectureNote.lesson_number, topic, content, study_date |
| ForeignKey и каскадное удаление | User → Course → LectureNote, on_delete=CASCADE |
| Регистрация, вход, выход | UserCreationForm, LoginView, LogoutView |
| Защищённые страницы | @login_required в journal/views.py |
| Изоляция пользователей | user=request.user и course__user=request.user при поиске объектов |
| Создание и изменение через ModelForm | CourseForm и LectureNoteForm с явным списком полей |
| Номер урока строго больше нуля | MinValueValidator(1) и CheckConstraint |
| HTML-наследование | Все страницы наследуют templates/base.html |
| Именованные маршруты и CSRF | {% url %} в ссылках, {% csrf_token %} в каждой POST-форме |
| Логика в Python | Выборки, агрегация и проверка владельца во views.py |
| Django 6.x, Python 3.14+, SQLite | Проверено на Python 3.14.10 и Django 6.0.10 |
| Зависимости и окружение | requirements.txt, .python-version, локальная .venv |
| Не менее 8 коммитов | История последовательных этапов включена в папку .git |

Дополнительные ограничения: продолжительность курса положительная, номер урока уникален внутри курса, дата изучения не в будущем, пустые обязательные поля отклоняются на сервере. Удаление выполняется только POST-запросом после страницы подтверждения.

## Маршруты

| Адрес | Назначение |
|---|---|
| `/` | Главная страница |
| `/accounts/signup/` | Регистрация |
| `/accounts/login/` | Вход |
| `/accounts/logout/` | Выход, только POST |
| `/dashboard/` | Курсы и статистика текущего пользователя |
| `/course/add/` | Новый курс |
| `/course/<id>/` | Курс и его конспекты |
| `/course/<id>/edit/` | Изменение курса |
| `/course/<id>/delete/` | Подтверждение и удаление курса |
| `/course/<id>/note/` | Новый конспект выбранного курса |
| `/note/<id>/edit/` | Изменение конспекта |
| `/note/<id>/delete/` | Подтверждение и удаление конспекта |

## Проверки

```powershell
.\.venv\Scripts\python.exe manage.py test
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
git log --oneline
git status --short
```

В `journal/tests.py` есть 31 тест. Они проверяют регистрацию и вход, анонимный доступ, изоляцию двух пользователей, подмену владельца и курса, CSRF, ошибочные данные, безопасный вывод HTML, ограничения БД и каскадное удаление. Тестовая БД создаётся и удаляется автоматически. В браузере дополнительно проверены регистрация, создание курса и конспекта, дата по умолчанию и обновление панели.

## Как сдать через GitHub

Подробная последовательность находится в [GITHUB.md](GITHUB.md). Используй существующую папку `.git`, чтобы сохранить историю. Не загружай только отдельные файлы через веб-интерфейс: так восемь коммитов не перенесутся.

История создана инструментом разработки с локальной подписью `Codex <codex@localhost>`. Это не GitHub-аккаунт. Перед будущими собственными коммитами задай свои `user.name` и `user.email`, как показано в инструкции. История не задним числом переписана под студента.

## Условия использования

Настройки рассчитаны на локальную учебную демонстрацию. `DEBUG=True`, резервный SECRET_KEY для разработки и `runserver` предназначены для этого режима. Для публикации приложения как интернет-сервиса нужна отдельная настройка сервера и секретов; для сдачи по условию требуется ссылка на исходный Git-репозиторий.
